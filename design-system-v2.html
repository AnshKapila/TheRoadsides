Motion & Micro-Interactions

Purposeful, content-aware motion. Never repeat one identical fade-up-on-scroll effect down the whole page. Motion should feel alive, varied, and tied to what each piece of content actually is.

Decision Authority: Use judgment per section. A hero doesn't need to move like a footer; a stat block shouldn't animate like a pull-quote. Mix patterns across the page.

  • Scroll entry, text blocks: fade + slight upward rise (8-16px), 400-500ms, ease-out
  • Scroll entry, images/cards: fade + slight scale (0.98 → 1), 400-500ms
  • Scroll entry, grouped items: staggered entry, 60-100ms delay between siblings
  • Hover, image/content cards: subtle image scale to 1.03-1.05; heading stays visible, description reveals on hover only (fade + slight rise)
  • Hover, buttons: color-shift per button spec, plus small icon shift (translateX 2-4px)
  • Hover, text links: underline animates in from the left
  • Pull-quotes: arrive a beat after surrounding content (slightly delayed fade) to give a distinct moment

Timing: Hover/micro-interactions 150-300ms; scroll-entry animations 400-600ms. Easing: ease-out for things entering, ease-in-out for hover states.

Accessibility: Respect prefers-reduced-motion — provide a static fallback (content simply present, no animation).

AVOID: Applying the identical animation pattern to every section with no variation. Motion must be content-aware.

What to Avoid

Checked against known tells of a generic, templated, AI-built site.

AVOID
  • ALL-CAPS tracked-out eyebrow labels above every heading
  • Numbered markers (01/02/03) on content that isn't a real sequence
  • Identical cards with the same shadow, icon-heading-line pattern repeated block after block
  • Gradient washes as background decoration (the hero's photographic lighting is the one exception)
  • Button or link text ending in an arrow (→)
  • Fade-up/slide-in scroll animation applied to every section
  • Fake initials-in-circle avatars, or testimonials with no real name/photo
  • Round, unsourced stats ("10K+", "98%") — every number must be real and specific
  • Logo walls with no context per logo
  • Default favicon or leftover site-builder branding
  • Emoji in headings
  • Vague buzzwords ("seamless," "scalable," "next-generation") without specifics underneath
DO
  • Left-align body text and most section content
  • Vary block structure between entries in a list (Our Work, Recognition) rather than repeating one template
  • Say what a link does in plain words ("Read the case study")
  • Include a real registered address and working contact info in the footer
  • Give every Recognition item real, specific context — publication, date, what it was for
  • Keep Brick rare and purposeful — highlight text and eyebrows only
  • Provide one-click access to a real human (WhatsApp/contact) from the homepage
